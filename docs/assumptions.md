# Assumptions and defaults

Decisions taken without asking because they do not change the design. Each one
can be revisited; the line says where to change it.

| # | Phase | Assumption / default | Where to change |
|---|-------|----------------------|-----------------|
| A1 | 0 | The repository root is the TestKit project; `testkit.yaml` at the root is found by walking up from the working directory (or `TESTKIT_ROOT`). | `testkit.yaml` |
| A2 | 0 | Go module path `github.com/tuannm99/testkit/testkit` (TestKit) and `.../reference-worker`; tied together with `go.work`. Go 1.24 (`GOTOOLCHAIN=local`), dependencies chosen to stay compatible with it. | `go.work`, `*/go.mod` |
| A3 | 0 | The CLI drives Docker through the `docker` / `docker compose` CLI (not the Engine SDK): it is the one dependency every host has and every command is reproducible by copy-paste (`-v` prints them). Compose ≥ 2.20 is required for `up --wait`. | `core/infra` |
| A4 | 0 | Hosts with only Docker use `./tk`, which builds `testkit/runner` (CLI + docker CLI) and runs it with the docker socket and the project mounted at the same absolute path. Lifecycle commands (`up/down/doctor/status/lint/plan`) run outside the TestKit network so that `down` can remove it; the others join it. | `tk` |
| A5 | 0 | Every host port is published on `127.0.0.1` only, from `infra/compose/testkit.env`. A second independent stack on the same host = override `TESTKIT_PROJECT`, `TESTKIT_NETWORK`, `TK_PORT_*`. | `infra/compose/testkit.env` |
| A6 | 0 | Credentials in `testkit.env` are test-only and protect throw-away containers. Real secrets are never written in the repository; override through the environment. | `infra/compose/testkit.env` |
| A7 | 0 | Postgres runs with `fsync=off`, `synchronous_commit=off` and data on tmpfs: data is disposable and speed matters. Tests about database durability are out of scope of the default stack. | `docker-compose.yml` |
| A8 | 0 | Kafka: single KRaft broker (`apache/kafka`), `auto.create.topics.enable=false` (TestKit creates namespaced topics), `group.initial.rebalance.delay.ms=0` (faster tests). | `docker-compose.yml` |
| A9 | 0 | Mongo runs as a single-node replica set `rs0` so transactions/change streams work. From the host the CLI connects with `directConnection=true`. | `docker-compose.yml`, `core/config/endpoints.go` |
| A10 | 0 | `TK_NOFILE_LIMIT` (default 65536) is the RLIMIT_NOFILE of Elasticsearch/ClickHouse; `doctor` verifies the engine accepts it. Hosts that cap it (the CI sandbox caps at 20000) lower it. Single-node ES skips its bootstrap checks so a lower value only matters for very large loads. | `testkit.env` |
| A11 | 0 | Images TestKit builds (`mockhub`, `runner`, services under test) are tagged with `TESTKIT_VERSION` / the service descriptor tag; builder and base images are pinned in `versions.env` and passed as build args. Behind a TLS-intercepting proxy set `TESTKIT_BUILD_CA=<pem>`: it is mounted as a BuildKit secret, never baked into images. | `versions.env`, `core/infra/build.go` |
| A12 | 0 | `ghcr.io/shopify/toxiproxy` is the default Toxiproxy image. MinIO no longer publishes images on Docker Hub (pull fails); object storage for `pack` is decided in Phase 6. | `versions.env` |
| A13 | 0 | The reference worker is the system under test that proves TestKit end to end. Failpoints exist only in the image built with `-tags failpoint` (`test_tag` in the descriptor); `TK_FAILPOINTS="name;name=once"` activates them, `once` survives container restarts through a marker file. | `reference-worker/internal/failpoint` |
| A14 | 0 | Mock namespaces are path based (`/ns/{ns}/{mock}/...`): the service under test receives the namespaced base URL in its env, so isolation needs no cooperation from the service. | `adapters/mock/http` |
| A15 | 0 | Webhook signatures from the Mock Hub: header `X-Signature: sha256=<hex HMAC-SHA256(secret, body)>` (configurable header name). Other schemes can be added per mock. | `adapters/mock/http/hub.go` |
| A16 | 1 | Container resources (USE) come from `tkstats` (Docker Engine stats API → Prometheus, cAdvisor metric names) instead of cAdvisor: cAdvisor v0.49–v0.52 cannot resolve containers when the engine uses the containerd image store (Docker ≥ 29 default). | `testkit/adapters/collect/dockerstats` |
| A17 | 1 | The OpenTelemetry collector image ships no shell, so TestKit builds `testkit/otel-collector` = pinned upstream image + a static `tkprobe` binary for its health check. | `testkit/Dockerfile` |
| A18 | 1 | Grafana allows anonymous *Viewer* access so dashboard links in reports open without login; it is bound to 127.0.0.1. API calls (annotations, render) use the admin test credentials. | `docker-compose.yml` |
| A19 | 1 | Annotations are organisation-wide with tags `testkit` + `<run_id>` (+ kind: step, fault, ...); every TestKit dashboard shows annotations matching both tags, so each run only sees its own. | `infra/grafana/dashboards` |
| A20 | 1 | Raw evidence data is fetched with the panel's own queries read from Grafana (variables interpolated, `$__rate_interval = max(step + scrape, 4 × scrape)`), at step = scrape interval (2 s) or coarser to keep ≤ 600 points. Loki metric queries start on the next step boundary so every sample lies inside the window. | `adapters/collect/grafana` |
| A21 | 1 | Metrics get `run_id/ns/service/case/trigger` from container labels at scrape time (Prometheus docker_sd), logs from the same labels (Alloy). Services under test therefore need no code change to be labelled; they only expose `/metrics` and log to stdout. | `infra/prometheus`, `infra/alloy` |
| A22 | 2 | Scenario DSL: `given` keys are expanded in a fixed order whatever their YAML order — store fixtures (`<store>.<entity>`), then mocks (`mock.<name>`), then jobs (`job`) — followed by explicit `steps`. `plan` prints the expansion. | `core/scenario` |
| A23 | 2 | Assertions are polled (`within`, default 30 s, 200 ms→1 s backoff), then the execution's trigger is drained (Kafka lag 0 / no queued-running job) and every assertion is evaluated **once more**; the final value decides. A value that held and then changed (e.g. a late extra call) fails with both timestamps. | `core/orchestrator` |
| A24 | 2 | Check arguments naming a scenario var resolve to its value (`mail.to(customer)`), so recipients can embed the namespace for isolation. Mailpit has no namespaces: mail isolation relies on recipients containing `{{ .ns }}`. | `core/orchestrator`, `adapters/mock/mail` |
| A25 | 2 | One namespace per execution (`tk_<run>_<n>`): database, topics, consumer group, ES index, mock base path, container name. Executions of one run can therefore run in parallel (`--parallel`). | `core/kit.Namespace` |
| A26 | 2 | Preliminary failure classes are rule based: provisioning/infrastructure/unevaluable check → *environment*; a failed assertion on a healthy environment → *product*; invalid scenario at run time → *test*; failed then passed on `--retries` → *flaky* (never counted as pass). | `core/orchestrator` |
| A27 | 2 | Functional evidence panels are cumulative counters (calls by code, jobs by result, side effects): a case lasts seconds and rates need several samples. Services under test are scraped every 1 s; the orchestrator waits for a baseline sample before the first step and for a sample after the case, and renders the window [first step − 2 s, end + 2 s]; annotations mark the exact step boundaries. Rate panels stay for performance runs. | `infra/prometheus`, `infra/grafana`, `core/orchestrator` |
| A28 | 2 | TestKit-built images carry a `testkit.source_hash` label (hash of the build context); `up`/`run` rebuild an image exactly when its sources changed, so a stale Mock Hub or service image can no longer produce misleading results. | `core/infra/build.go` |
| A29 | 2 | Report language is Vietnamese (QC readers); identifiers, checks and evidence paths stay as in the files. | `core/report` |
| A30 | 3 | The Mock Hub journals a call **when it arrives** (`in_flight`) and completes the entry when answered; `mock.<x>.succeeded` counts 2xx answers actually delivered and not replayed (real side effects at the provider). A call abandoned by the client (crash, timeout) is not a charge in the mock's model. | `adapters/mock/http` |
| A31 | 3 | Hard crash tests restart the same container (`sut.kill` + `sut.start`, or `restart: on-failure` with a failpoint); the host-published health port is resolved again after every start. Kafka redelivery after a hard crash waits for the consumer session timeout, so the reference worker exposes `KAFKA_SESSION_TIMEOUT` (default 45 s, 10 s in the crash case). | `adapters/sut`, reference worker |
| A32 | 3 | Trigger parity: for a case run through several triggers, the result and the observed value of every assertion must be identical; cases where an execution errored are not compared. A mismatch fails the run. | `core/orchestrator` |
| A33 | 3 | `assert.during` observes a condition continuously for a duration (e.g. a job must not run before `run_at`); it is an observation window, not a sleep. | `core/orchestrator` |
| A34 | 3 | Webhook payload versions accepted by the reference worker: `2024-06-01`; others answer 422. Signature `X-Signature: sha256=<hmac>` with the mock's test-only secret, injected into the service env with `{{ mocksecret "psp" }}`. | reference worker, descriptor |
| A35 | 3 | Contract tests (`adapters/trigger/contract`) run against the real stack with `TESTKIT_INTEGRATION=1`; every trigger in the table (Kafka, DB poll; RabbitMQ/SQS if added) must pass the same suite. | `adapters/trigger/contract` |
| A36 | 4 | Socket protocol default (section 9 still open): WebSocket with JSON text messages (`{"id":…}` acked by `{"ack": id}`, `{"type":"ping"}`/`pong` heartbeat) and TCP with `line` or `length32` framing. Other codecs (ISO 8583, FIX) plug in as a framer; the reference worker only uses WebSocket, TCP is covered by unit tests. | `adapters/mock/socket` |
| A37 | 4 | SMTP mock: the namespace is read from the envelope sender `local+<ns>@domain` (descriptor sets `MAIL_FROM`), one scripted behaviour per session (last repeats); accepted mail is relayed to Mailpit so `mail.*` checks work unchanged. | `adapters/mock/smtp` |
| A38 | 4 | ClickHouse checks run `SYSTEM FLUSH ASYNC INSERT QUEUE` first (consistency wait); `clickhouse.<entity>.duplicates` = rows − distinct keys. The reference worker inserts synchronously with `insert_deduplication_token` on a MergeTree with `non_replicated_deduplication_window`. `clickhouse.optimize` is available for ReplacingMergeTree tables. | `adapters/store/clickhouse` |
| A39 | 4 | Redis isolation is the key prefix `<ns>:` given to the service; Mongo isolation is one database per namespace (dropped at teardown); Elasticsearch checks always `_refresh` first. | `adapters/store/*` |
| A40 | 4 | Reconcile compares id sets (count, duplicates, missing ids, sha256 of the sorted set) across the stores declared in `reconcile:`; the report is written for every execution of a service that declares one. | `adapters/store/reconcile` |
| A41 | 4 | Half-open is simulated as total silence: the mock keeps the connection, never reads or answers until the namespace is reset (≤ 5 min); only a heartbeat can detect it. | `adapters/mock/socket` |
| A42 | 4 | Not covered yet: Redis lock expiring mid-job (the reference worker locks in Postgres), Mongo change streams, GreenMail/IMAP (the reference worker does not read mail). | — |
| A43 | 5 | Toxiproxy is built from source at a pinned version (v2.9.0) in `testkit/Dockerfile`, so the stack does not depend on ghcr.io. Each execution gets its own proxies `<ns>_<dependency>` on a random port; the service under test is given the proxy address instead of the real one (`chaos.proxies` in the descriptor). | `adapters/chaos/toxiproxy` |
| A44 | 5 | Packet-level faults (loss, jitter, reorder) use `tc netem` from `nicolaka/netshoot:v0.13` joined to the service container's network namespace. They need NET_ADMIN **and** the `sch_netem` kernel module; `testkit doctor` probes both and reports a `netem` capability. Without it the case is skipped with class `capability`, listed in the run notes, never failed. | `core/infra/doctor.go`, steps |
| A45 | 5 | Faults that break shared infrastructure (pausing Postgres, stopping a store) run **exclusively**, after the parallel batch, so they cannot disturb other executions; faults scoped to one namespace (Toxiproxy, the service's own container) run in parallel. | `core/orchestrator` |
| A46 | 5 | Chaos experiments follow steady state → fault → hold (with `abort_if` blast-radius conditions checked continuously) → clear → recovery. Recovery time = time from clearing the fault until every `chaos.recover` condition holds; the case declares the allowed maximum. | `core/orchestrator/experiment.go` |
| A47 | 5 | Load is an **open model** (constant arrival rate): jobs are sent on schedule whatever the worker's speed, so slowness shows up as latency instead of being hidden by a slower sender. The generator reports jobs it sent late; a late generator makes the case invalid, not the service slow. | `core/orchestrator/perf.go`, k6 `constant-arrival-rate` |
| A48 | 5 | End-to-end latency of a job = time its order turned `paid` in Postgres (DB clock) − time the generator sent it. Warm-up jobs are tagged and excluded. HTTP perf (k6) uses k6's own request timings. | `core/orchestrator/perf.go`, `adapters/exec/k6` |
| A49 | 5 | Each perf case is repeated (default 3) and medians are reported with every sample. A baseline (default 5 runs) is stored per **environment fingerprint** (CPU count, memory, docker version, hash of pinned images) in `testkit/baselines/<fingerprint>/<key>.json`; another machine has no baseline and the comparison is skipped with a note, never compared across machines. | `core/perf` |
| A50 | 5 | Regression = worse than the baseline median by more than the allowed ratio (default 10%) **and** statistically significant: one-sided Mann-Whitney U, exact distribution, α = 0.05. A large but noisy difference is reported as "worse, not significant". With fewer than 3 samples on either side the threshold alone decides. | `core/perf/stats.go`, `baseline.go` |
| A51 | 5 | A store outage (connection refused/reset, database shutting down) is not the job's fault: the reference worker retries it with capped backoff without consuming delivery attempts and never dead-letters it (TC-CHAOS-002; failpoint `outage_is_failure` restores the old behaviour for the mutation run). | reference worker |
| A52 | 5 | Mutation gate (`testkit admit`): a case is admitted when it is green on the unbroken system `--stability` times in a row (default 2) per trigger and red under every declared mutation (with the expected assertions red); perf cases also need a baseline comparison. A case without mutations is rejected. The gate only reports; `--approve --by <person>` records the approval and the run's manifest sha256 in the case file. Lint refuses a drafted case (`generated:`) marked approved without an admission. | `cmd/testkit/admit_cmd.go`, `core/orchestrator/admission.go` |
| A53 | 5 | Load generators are part of the test environment: a job they failed to enqueue (or did not send before `load.wait`'s timeout) makes the execution an *environment* error, never a product failure and never part of the service's error rate. Stopping a load stops new arrivals; sends already started always complete. | `core/orchestrator/experiment.go`, `perf.go` |
| A54b | 6 | QC handover is **tool-neutral CSV + Markdown** first (`qc.tool: files`, decided 2026-10-05): every bundle has `qc/testcases.csv|md` (one row per step, case fields repeated, so any importer — Jira plugins, TestRail, Excel — can map the columns) and `qc/results.csv|md` (one row per execution, plus the case verdict and the gate). CSVs are UTF-8 with BOM; cells a spreadsheet would run as formulas are prefixed with `'`. Other tools are added as exporters next to it (`qc.tool: files, zephyr-scale`). | `adapters/qc/files`, `adapters/qc/qcdata` |
| A54 | 6 | Zephyr Scale exporter (kept for the port, off by default): Jira with **Zephyr Scale** (the plugin with test cycles), **Cloud** API `https://api.zephyrscale.smartbear.com/v2` by default. Results use Zephyr Scale's custom format (version 1, one execution per test case: Passed if every trigger passed, else Failed); skipped cases are not exported but listed in the cycle description. Data Center (or Zephyr Squad / Xray) needs a different endpoint/format: `TK_QC_API` overrides the URL, other tools plug in as another exporter. To confirm with the team. | `adapters/qc/zephyr` |
| A55 | 6 | Test cases map to Zephyr by `qc_key` in the case file; without it, by name `<ID> — <title>` (Zephyr creates nothing unless `auto_create_test_cases: true`). The CSV for test case import has one row per step; requirement ids go to "Coverage (Issues)" and should be Jira issue keys in real use. | `adapters/qc/zephyr` |
| A56 | 6 | Environment: Docker only for now (no Helm/Kubernetes). | — |
| A57 | 6 | Third parties: REST and WebSocket only. Without a provider sandbox the mock is self-faked from the provider's documentation/OpenAPI and declared `verified_against: docs`; the report flags it as a residual contract risk. `sandbox` is used when a provider sandbox has been replayed against the mock. | descriptor, report |
| A58 | 6 | SLOs are set per case (`perf.thresholds`); the regression tolerance is 10 % by default, overridable per case (`baseline.max_regression`). | `core/scenario/perf.go` |
| A59 | 6 | Release gate (suite file, `kind: Suite`): GO only if no fail/error, no flaky outside an unexpired quarantine (owner, ticket, deadline), every mutation killed, triggers agree, no perf regression, every listed requirement covered by passing cases. Drafts are skipped and listed. With `allow_skipped_capability: true`, cases skipped for a missing privilege and requirements covered only by them are listed as "not verified on this host" instead of blocking. | `core/orchestrator/gate.go` |
| A60 | 6 | The bundle is a zip of the sealed run directory (sorted entries, fixed timestamps: packing twice gives the same bytes). `pack` refuses a bundle that changed since it was sealed or that contains a declared secret value (env names with PASSWORD/SECRET/TOKEN/…, mock secrets; ≥ 8 characters) or a credential pattern. | A61 | 6 | UI tests: Playwright TypeScript in `ui-tests/`, run in the pinned `mcr.microsoft.com/playwright` image (`PLAYWRIGHT_IMAGE`, same version as `@playwright/test`). | A62 | 7 | AI is optional and model-agnostic (decided 2026-10-05: "Claude or any model"): `ai.provider` = none (default: nothing sent, the redacted prompt is written for manual use, answer given back with `--response`) / anthropic (official Go SDK, default model `claude-opus-5-5`, effort `high`, server-side refusal fallback `default`; a refusal is an error, never an answer) / openai-compatible (any model behind `/chat/completions`) / command (any CLI on stdin, e.g. `claude -p`). `TK_AI_PROVIDER|MODEL|BASE_URL|COMMAND` override per command. | `adapters/ai/*`, `cmd/testkit/ai_cmds.go` |
| A63 | 7 | Only redacted data leaves the machine (decided 2026-10-05). The task text is built from selected fields only (assertions, reasons, timeline, last 40 log lines, evidence file names — never snapshots or mail bodies), then redacted: declared secrets, URL credentials, sensitive key=value pairs, Authorization headers, JWTs, e-mails, card numbers (Luhn), 9–19 digit numbers, phone numbers, IPv4 (except loopback), random-looking tokens (hex ≥ 32 or entropy ≥ 4.2 bits/char) → stable placeholders (`<email-1>`). A guard re-scans and **refuses to send** if a declared secret, credential pattern, e-mail or card number remains. Every request is recorded redacted (payload, sha256, redaction counts, answer) under `ai/requests/` of the bundle or `out/ai/drafts/`. Free-text personal names are not detectable by pattern: evidence must not contain real personal data in the first place (test data only). | `core/ai/redact.go`, `core/ai/client.go` |
| A64 | 7 | AI output is advisory and validated deterministically: triage answers are accepted only for executions that were asked about, with a known category; cited files that do not exist are dropped and reported; TestKit's rule class stays authoritative next to the suggestion. Summaries start with TestKit's own facts and are flagged when they contradict the gate decision. AI tasks never rewrite `run.json` or other result files (only `report.html` is re-rendered, and the bundle is re-sealed). | `core/ai/triage.go`, `core/ai/summary.go` |
| A65 | 7 | Drafted cases: the model writes YAML from the vocabulary (`testkit steps`), the service descriptor and two approved examples; TestKit then forces `id`, `status: draft`, `requirement` (`--req-id`, else `REQ-TBD`), `generated:` provenance, and removes `owner`, `admission`, `qc_key`; lint errors are sent back for up to 2 repair rounds; then a person runs `admit` and approves. | `core/ai/draft.go` |
| A66 | 7 | The explicit `trigger.drain` step no longer turns a timeout into an environment error: jobs still pending means the service did not finish its work, which the assertions judge (as for the drain at the end of every case). | A67 | 7 | Agent guide: `AGENTS.md` (any agent; `CLAUDE.md` imports it). Prompts are embedded and versioned (`core/ai/prompts`, `PromptVersion` recorded with every request). | `AGENTS.md`, `core/ai/prompts` |
